# Meowcall - dbSupport

The `dbSupport` package contains the meowcall database schema (SQLAlchemy ORM models) and Atlas database migrations. It is **not** the DB engine/session infrastructure — that lives in `db/`.

## Package Layout

```
packages/dbSupport/
├── atlas.hcl          # Atlas migration configuration
├── loadModels.py      # Entry point for Atlas DDL generation
├── pyproject.toml     # Package metadata
├── migrations/        # Atlas migration SQL files
└── src/
    └── models/
        ├── __init__.py    # Re-exports all models, enums, and helpers
        ├── base.py        # Base class, enums, cuid() helper
        ├── users.py       # User, UserConnection, Blacklist
        ├── servers.py     # Server, ServerConfig
        ├── messages.py    # Messages, MessageStatus
        ├── moderation.py  # Infractions, appeals
        ├── reports.py     # HubReport
        ├── calls.py       # UserphoneCall
        └── misc.py        # Miscellaneous models
```

## Atlas Import Chain

Atlas uses an external schema provider to discover the SQLAlchemy models and generate DDL. The chain works as follows:

### 1. `atlas.hcl`

The Atlas config (`atlas.hcl`) defines an `external_schema` block that invokes `loadModels.py`:

```hcl
data "external_schema" "sqlalchemy" {
  program = [
    "uv",
    "run",
    "-q",
    "loadModels.py",
    "postgresql"
  ]
}
```

### 2. `loadModels.py`

This script adds `src/` to `sys.path`, imports `Base` from `models`, and calls `dump_ddl()`. By importing `Base`, it triggers the import of every model module:

```python
from models import Base

if __name__ == '__main__':
    dialect = sys.argv[1] if len(sys.argv) > 1 else 'postgresql'
    dump_ddl(dialect, [Base.metadata], [])
```

### 3. `src/models/__init__.py`

This file imports every model class and enum from every model module (`hubs.py`, `users.py`, `servers.py`, etc.) and re-exports them. When `loadModels.py` does `from models import Base`, Python executes `__init__.py`, which triggers the import of all model submodules. This registers every table with `Base.metadata`, making them visible to Atlas.

### Adding a New Model

1. Create the new model file in `src/models/` (e.g., `myFeature.py`)
2. Define your model class(es) inheriting from `Base`
3. Import and re-export the new classes in `src/models/__init__.py`
4. Generate the migration: `atlas migrate diff "add_my_feature" --env sqlalchemy`
5. Apply: `atlas migrate apply --url "URL"`

> **Important:** If a model is not imported in `__init__.py`, Atlas will not see it and no migration will be generated for it.

## Runtime Usage

At runtime, the bot imports models as `from models import User, ...` — the package is available as `models`, not `dbSupport`. This is configured via the package path setup.

## Migrations

Migration files live in `migrations/` and are plain SQL generated by Atlas. They are applied with:

```bash
atlas migrate apply
```

Check migration status with:

```bash
atlas migrate status
```
